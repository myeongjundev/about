# 포트폴리오 리디자인 설계 — Selected Builds

작성: 2026-09-20 · 상태: 5차 품질 검증

## 목표

- 자기소개 과제의 사실과 문구는 바꾸지 않는다.
- 사이트 자체가 프론트엔드 구현 역량의 증거가 되게 한다.
- 긴 본문을 읽는 동안 비어 보이던 왼쪽 열을 실제 작업 화면으로 채운다.
- 페이지 스크롤 하나만 사용하고 카드 내부 스크롤은 만들지 않는다.

## 참고 사이트에서 가져올 원칙

- Bruno Simon: 포트폴리오 자체가 기억에 남는 하나의 경험이어야 한다.
- Jacek Jeznach: 강한 타이포그래피와 절제된 모션으로 개발자의 성격을 드러낸다.
- Oak Harbor Web Designs: 설명보다 실제 화면과 결과를 먼저 보여 준다.

3D 월드, 사운드, 커스텀 커서처럼 콘텐츠보다 앞서는 장치는 복제하지 않는다. 이 사이트는
실제 프로젝트 이미지, CSS 기반 스택, 빠른 정적 페이지로 같은 목적을 달성한다.

## 정보 구조

```text
왼쪽                               오른쪽
프로필 카드                         이야기
Selected Builds                    숫자
  01 CLOV                          대표작 상세
  02 T10 침입 탐지 연구             경력과 과제
  03 ALTER / EGO                   문서와 연락
  04 T08 Passkey
```

- 왼쪽 카드는 오른쪽 상세 항목의 앵커로 연결한다.
- 오른쪽은 상황·행동·결과와 검증 링크를 유지한다.
- 같은 프로젝트가 반복되어도 왼쪽은 시각적 인덱스, 오른쪽은 근거와 설명으로 역할이 다르다.

## 상호작용

- 첫 프로필 카드의 HOW I WORK에서 DESIGN·BUILD·SHIP을 직접 선택해 작업 방식 문장을 확인한다.
- 정밀 포인터가 있는 화면에서는 프로필 카드의 조명이 포인터를 따라가며, 터치 화면에는 적용하지 않는다.
- 데스크톱: 프로젝트 카드가 페이지 스크롤에 맞춰 순서대로 겹쳐 쌓인다.
- 카드 hover: 실제 화면만 미세하게 확대하고 카드 전체를 4px 들어 올린다.
- 클릭: 해당 대표작 또는 경력 항목으로 이동한다.
- 대표작의 Case Notes를 열면 문제·판단·구현·검증을 2×2 구조로 확인한다.
- 모바일: 보조 레일을 숨기고 기존 대표작·경력 카드만 노출한다.
- `prefers-reduced-motion`에서는 전환을 사실상 제거한다.

## 콘텐츠 선정 기준

1. 공개 화면 또는 재현 자료가 있다.
2. 맡은 역할과 결과가 사실로 승인되어 있다.
3. 서로 다른 역량을 보여 준다.

현재 선정: CLOV(협업·풀스택·배포), T10(데이터·보안·연구), ALTER / EGO(UI·Canvas·검증),
T08(인증·WebAuthn).
목록은 `approved.json`의 공개 완료 항목에서 자동으로 구성한다.

## 품질 측정

- 외부 웹 폰트 요청을 제거하고 운영체제 기본 글꼴 스택을 사용한다.
- Lighthouse 모바일 최종: 성능 100, 접근성 100, 모범 사례 100, SEO 100.
- Lighthouse 데스크톱: 성능 100, 접근성 100, 모범 사례 100, SEO 100.
- 모바일 FCP 1.1초, LCP 1.2초, CLS 0, 초기 전송량 70KiB.
- 데스크톱 FCP 0.3초, LCP 0.3초, CLS 0.
- 색상 대비, 강제 리플로우, 미사용 CSS·JavaScript 검사를 모두 통과했다.
