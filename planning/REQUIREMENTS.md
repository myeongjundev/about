# 마지막 과제 A(12번) 요구사항 정리

원문: 동기에게서 받은 과제 안내 텍스트(2026-09-17). 원문 파일은 이 저장소에 넣지 않고,
아래에 조건과 제출물만 요약한다. 원문에 함께 붙어 있던 리추얼 기록 예시는 **동기의 기록**이므로
설계·수치 어디에도 쓰지 않는다. 본인 과제 화면이 열리면 원문을 다시 대조한다.

## 한 줄 요약

처음 온 사람이 3분 안에 읽고 함께 일하고 싶어지는 **공개 사이트 1개**를 만들고,
**이력서·자기소개서·경력기술서 문서**와 새 기록으로 사이트 숫자·문단 후보를 다시 만드는
**장치(ZIP)**를 함께 낸다.

## 사이트에 들어갈 것

| 자리 | 내용 | 비고 |
|---|---|---|
| 첫 화면 | 본인 이름 + "…한 사람"으로 끝나는 한 줄 소개 + 이야기·숫자·대표작·이력서 입구 | 한 줄 소개·첫 문장·마지막 문장은 본인이 직접 쓴다 |
| 이야기(본편) | 11번 소설에서 뽑은 1,500자 안팎 자기소개. 고난 → 다시 일어난 날 → 더 나아진 지금 | 소설 자체는 넣지 않는다. 각색은 사실로 되돌린다. 토막마다 날짜 있는 장면 |
| 세 능력 | 자기조절력·대인관계력·자기동기력이 이야기 속 장면으로 드러남 | |
| 숫자 칸 | 13주 기록의 숫자 + 출처(내 출석 기록 / 리추얼 기록 / 내 제출 현황) | 회복탄력성·과제지속력 근거. 숫자 하나는 고난 장면과 짝짓기. 작은 숫자도 그대로 |
| 대표작 | CLOV 프론트엔드·백엔드 저장소 + 10번 논문(로그인 없이 열림) | 공개가 끝난 결과물만 둔다. T13은 완료 후 추가한다 |
| 연락 | 본인 이름 + 공개하기로 정한 연락 수단 하나 | 다른 사람 실명 금지 |
| 필요 없음 | 방문자 통계, 댓글, 로그인 | 디자인 미평가 |

## 제출물

1. 결과물 URL 1개 — 로그인 없이 열리는 HTTPS 공개 사이트
2. 문서 파일 — 이력서·자기소개서·경력기술서
3. 장치 ZIP — 실행 소스·README·마지막 결과 (문서와 하나로 묶어도 됨)
4. 제출문 — 짧은 확인 방법 + AI와 나의 판단 세 줄

## 채점 관점 (증거 보관 기준)

디자인은 보지 않는다. 아래 네 가지만 본다.

1. 이야기가 고난에서 시작해 더 나아진 지금으로 끝나는가
2. 장면에 날짜가 있는가
3. 숫자가 출처와 함께 있는가
4. 장치가 같은 입력에 같은 결과를 내는가
