# 설계 초안

작성: 2026-09-17 · 상태: 초안(본인 과제 화면과 리추얼 기록을 받은 뒤 확정)

## 1. 전체 흐름

```text
inputs/ (Git 제외)                device/                       docs/ (공개 사이트)
  ritual.json        ──┐
  tasks.csv          ──┼─▶ refresh.py ─▶ out/numbers.json ─┐
  attendance.json    ──┘              └▶ out/candidates.md  │  (사람이 읽고 고름)
                                                            ▼
                                  device/approved.json ─▶ build_site.py ─▶ docs/data/site.json
                                                                        └▶ documents/ (문서 빌드 입력)
```

- **사람이 승인한 문장만** 사이트와 문서에 들어간다. 후보는 제안일 뿐이다.
- 사이트 문구(한 줄 소개, 이야기 첫·마지막 문장)는 본인이 `approved.json`에 직접 쓴다.

## 2. 저장소 구조

| 경로 | 역할 |
|---|---|
| `docs/` | 공개 사이트. 정적 HTML·CSS·JS, 데이터는 `docs/data/site.json`. GitHub Pages(main `/docs`) |
| `docs/files/` | 로그인 없이 받는 파일(10번 논문 사본이 필요할 때, 이력서 PDF 등) |
| `documents/src/` | 이력서·자기소개서·경력기술서 원고(Markdown) |
| `documents/build.py` | 원고 → DOCX (11번 빌드 도구 방식 재사용) |
| `device/` | 장치: `refresh.py`, `build_site.py`, `check_repeat.py`, `README.md`, `sample-inputs/` |
| `inputs/` | 실제 기록. **Git 제외** |
| `planning/` | 요구사항·설계·진행 기록 |

## 3. 사이트 화면 (3분 안에 읽히는 순서)

1. **첫 화면** — 김명준 · "…한 사람" 한 줄 소개 · 입구 4개(이야기 / 숫자 / 대표작 / 이력서)
2. **이야기** — 1,500자 안팎, 세 토막(고난 · 다시 일어난 날 · 지금), 토막마다 날짜 장면으로 시작.
   각 토막 옆에 드러난 능력 표시(자기조절력·대인관계력·자기동기력).
3. **숫자** — 카드마다 숫자 · 무엇을 셌는지 · 출처(내 출석 기록 / 리추얼 기록 / 내 제출 현황) · 기준일.
   숫자 하나는 고난 토막과 연결 표시.
4. **대표작** — CLOV(실제 화면, 프론트엔드·백엔드 저장소) · 10번 논문(실제 차트, 공개 링크, 한 줄 요약)
5. **문서와 연락** — 이력서·자기소개서·경력기술서 받기 · 공개 연락 수단 1개

기술: 빌드 도구 없는 정적 페이지(HTML/CSS/바닐라 JS). 데이터가 없을 때도 본문이 보이도록
핵심 문구는 HTML에도 들어가게 빌드한다.

### 사실로 되돌릴 11번 소설의 각색 (사이트에 쓰지 않거나 확인 후 사용)

- 12장 "빈 저장소에 첫 번째 이슈를 열었다" — 상징적 결말. 실제 새 프로젝트를 시작했는지 확인 필요.
- 1장 P028 끝 "그곳의 순서를 익히는 데서 시작했다", P029 끝 "가장 분명한 약속" — 해석 문장.
- 2장 P001 끝 "의심하며 미루기보다 먼저 써 보는 쪽을 택했다" — 해석 문장.
- "하루 2만 보" — 기억이 불확실한 수치. 사이트에는 쓰지 않거나 "많이 걸었다"로.
- 소설의 대화·마음 묘사 전반 — 사이트에는 행동과 결과만.
- CLOV 팀원 가명(도윤·지후·민석) — 사이트에서는 이름 없이 "팀원"으로.

## 5. 숫자 칸 (리추얼 기록 대기)

출처 세 곳에서만 옮긴다. 13주 과정 기준일을 함께 적는다.

과정 기간: **2026-08-11(화) ~ 2026-11-12(목)**. 평일 68일에서 공휴일을 빼면 전체 수업일은 62~63일이다.
공휴일 가정: 08-17 대체공휴일(출석 기록으로 확인), 09-24·25 추석, 10-05 개천절 대체공휴일, 10-09 한글날.
09-28 추석 대체공휴일은 아직 불확실하다. 전체 수업일은 장치 설정(과정 시작·끝일, 휴일 목록)으로 계산하고, 휴일은 학원 일정으로 확인한다.

| 후보 숫자 | 출처 | 연결 능력 | 상태 |

| 출석일 / 전체 수업일, 지각·결석 수 | 내 출석 기록 | 과제지속력 | **받음(09-18)** — 확정된 수업일 27일 중 출석 27일, 지각 0·결석 0 (08-11~09-17) |

## 6. 장치 설계

- 언어: Python 3.12 표준 라이브러리만(외부 API 없음) → 같은 입력이면 같은 결과.
- `refresh.py <입력폴더> <출력폴더>`
  - 리추얼 JSON: 날짜별 아침·마무리 기록 수 집계, 능력별 키워드 규칙으로 후보 문장 추출.
    동료·감사 대상 칸은 읽지 않고, 본문 속 이름 후보도 가린다.
  - 과제 목록 CSV: 제출 수·기한 준수 수, 과제별 능력 태그.
  - 출석 JSON: 출석률·지각·결석.
  - 출력: `numbers.json`(숫자·출처·기준일), `candidates.md`/`candidates.json`(능력별 후보 · 날짜 · 근거 ID).
  - 정렬 고정, 실행 시각·절대경로를 출력에 넣지 않음.
- `build_site.py` — `approved.json` + `numbers.json` → `docs/data/site.json`, 문서 원고 변수.
- `check_repeat.py` — 새 임시 폴더에 복사해 두 번 실행, 출력 SHA-256 비교 결과를 `out/repeat-check.txt`로 남김.
- 9번 과제의 공개 도구 `ritual-strength-agent`의 파서·원장 방식을 참고한다.
- AI 서비스는 쓰지 않는 것이 기본. 쓰게 되면 키는 환경 변수, README에는 변수 이름만.

## 7. 문서

- 자기소개서 본문 = 이야기 본편(사이트와 같은 사실).
- 이력서 = 이름, 연락 수단 1개, 학력, 교육 과정, 과제와 기간. 학력 등 공개 범위는 본인이 정한다.
- 경력기술서 = 과제 1개당 1줄: 과제 · 능력 · 상황 · 행동 · 결과.
  후보: CLOV(대인관계력), T10 논문(자기동기력), ALEPH 네트워크 실습 또는 T11(자기조절력) — 역할이 서로 다른 것으로 고른다.
- 형식: DOCX(필요하면 PDF 병행), 비밀번호 없음.
