# Claude Design 프롬프트 (2026-09-17)

디자인만 먼저 뽑는다. 내용이 정해지지 않은 곳은 모두 `[ ]` 자리표시로 둔다.

## 뽑기 전 주의

1. 숫자·경력·추천사·사진을 지어내지 않게 한다(채점: 숫자는 출처와 함께).
2. 다른 사람의 이름·사진·회사 로고를 넣지 않는다(BRA-C10).
3. 순수 HTML·CSS·JS, 상대 경로(GitHub Pages `/about/` 하위 경로).
4. 통계·댓글·로그인·추적 스크립트 없음(BRA-C13 시크릿 창).
5. 디자인은 채점하지 않는다. 첫 화면 10초, 요약 줄만으로 이야기 이해가 우선.

## 프롬프트

```text
나(김명준, 신입 개발자)의 자기소개 사이트를 디자인해 줘. 실제 채용 지원에 쓰는 사이트이고, 채용 담당자가 처음 들어와 3분 안에 "누구인지, 무엇을 해 왔는지, 왜 함께 일하고 싶은지"를 이해해야 해.

[결과물 형식 — 반드시 지켜 줘]
- 순수 HTML + CSS + 바닐라 JS 정적 페이지. React·Tailwind·빌드 도구 없이 index.html, styles.css, script.js로.
- GitHub Pages의 하위 경로(https://myeongjundev.github.io/about/)에 올린다. 모든 링크·이미지·스크립트는 상대 경로로.
- 한 페이지, 한 칼럼, 모바일 우선(폭 360px에서도 가로 스크롤 없음), 데스크톱 최대 폭 약 720~760px.
- 한국어 본문. 읽기 편한 한글 글꼴(Pretendard 또는 시스템 글꼴)과 넉넉한 줄 간격.
- 라이트·다크 모드 모두 대비가 충분하게. 키보드로 모든 링크 이동 가능, 섹션마다 id 앵커.
- 방문자 통계, 댓글, 로그인, 쿠키 배너, 외부 추적 스크립트, 폼은 넣지 마.
- 인쇄(PDF 저장) 시에도 깔끔하게 보이도록 print 스타일 포함.

[절대 지어내지 말 것]
- 숫자, 날짜, 회사명, 경력, 수상, 추천사, 프로필 사진, 다른 사람 이름을 새로 만들지 마.
- 내용이 정해지지 않은 곳은 모두 대괄호 자리표시로 남겨 줘. 예: [한 줄 소개 — 본인 작성], [숫자], [출처], [YYYY.MM.DD].
- 아래에 내가 준 문장만 실제 문장으로 써.

[화면 구성 — 이 순서 그대로]
1. 첫 화면(#top) — 스크롤 없이 보이는 영역에 이것만:
   - 이름: 김명준
   - 직무 표기: [직무 — 예: 신입 풀스택·인프라 개발자]
   - 한 줄 소개: [○○한 장면을 거쳐 ~하는 사람 — 반드시 "…한 사람"으로 끝남, 본인 작성]
   - 입구 버튼 4개: 이야기(#story) · 숫자(#numbers) · 대표작(#works) · 이력서(#documents)
   - 연락 수단 1개: [공개 연락 수단 — 본인 결정]
   - 큰 일러스트나 배경 영상 없이 글자 중심으로. 10초 안에 이름·직무·한 줄 소개가 읽혀야 함.

2. 이야기(#story) — 이 사이트의 본편(전체 약 1,500자)
   - 세 토막 카드: ① 고난 ② 다시 일어난 날 ③ 더 나아진 지금
   - 토막마다 맨 위에 [YYYY.MM.DD] 날짜 + 굵은 요약 한 줄([요약]) → 그 아래 본문 문단([본문]).
     요약 줄만 훑어도 고난→회복→지금 흐름이 이해되게 시각적으로 강조해 줘.
   - 토막마다 작은 능력 배지: 자기조절력 / 대인관계력 / 자기동기력 중 해당하는 것([능력]).
   - 이야기 첫 문장과 마지막 문장은 따로 돋보이게(본인이 직접 쓴 문장 자리: [첫 문장], [마지막 문장]).
   - 숫자 카드 하나와 고난 토막을 연결하는 작은 표시(예: "이 시기의 기록 → 숫자 보기").

3. 숫자(#numbers) — 회복탄력성·과제지속력의 근거
   - 카드 3~4개. 카드마다: [큰 숫자] / 무엇을 셌는지 [설명] / 출처 배지(내 출석 기록 · 리추얼 기록 · 내 제출 현황 중 하나) / 기준일 [YYYY.MM.DD].
   - 작은 숫자(예: "13주 중 9주")도 그대로 보여 주는 정직한 디자인. 과장된 그래프·애니메이션 카운터는 쓰지 마.
   - 카드 하나에 "고난 장면과 연결" 표시 자리.

4. 대표작(#works) — 2칸
   - 칸 1: 10번 논문 — 제목 [논문 제목], 한 줄 요약 [요약], 무엇을 했는지 [문제 → 방법 → 결과], 기술 태그 [태그], 로그인 없이 열리는 링크 [URL].
   - 칸 2: 13번 앱 — "13번 과제를 마친 뒤 채웁니다" 안내와 예정일 [YYYY.MM.DD]. 빈자리임이 분명하지만 성의 있게 보이는 빈 상태 디자인.

5. 과제 타임라인(#timeline)
   - 항목마다: 기간 [YYYY.MM ~ YYYY.MM] · 과제/프로젝트명 [이름] · 능력 배지 [능력] · 상황 [ ] · 행동 [ ] · 결과 [숫자 포함] · 기술 태그.
   - 3~5개 자리. 최신순. 한국 개발자 이력서처럼 짧은 불릿.

6. 문서와 연락(#documents)
   - 받기 버튼 3개: 이력서 · 자기소개서 · 경력기술서 ([파일 링크]).
   - 연락 수단 1개 다시 표시.
   - 바닥글: "이 사이트의 숫자와 문단 후보는 새 기록을 넣으면 다시 만들어집니다 · 마지막 갱신 [YYYY.MM.DD]".

[데이터 구조]
- 위 모든 자리표시 내용은 data/site.json 한 파일에서 읽어 채우도록 script.js를 작성해 줘.
- 단, JS가 꺼져 있어도 HTML에 들어 있는 기본 내용(자리표시)이 그대로 보이게 해 줘.
- site.json 예시 구조도 함께 만들어 줘: profile(name, role, tagline, contact), story(firstSentence, lastSentence, segments[date, summary, body, abilities]), numbers[value, label, source, asOf, linkedSegment], works[title, summary, problem, method, result, tags, url, status, plannedDate], timeline[period, title, abilities, situation, action, result, tags], documents[label, href], updatedAt.

[톤]
- 차분하고 신뢰감 있는 문서형 디자인. 장식보다 여백·타이포그래피·분명한 섹션 제목.
- 과장 표현("최고의", "열정 넘치는") 대신 날짜와 사실이 앞에 오는 문구 배치.
```

## 받은 뒤 확인할 것

- 외부 스크립트(통계·폰트 외)가 없는지
- 360px 폭 가로 스크롤, 다크 모드 대비
